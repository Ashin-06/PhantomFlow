# Audit and verification — 2026-10-09

## Changes

- Removed the unconditional administrator demo token. Development login now
  requires both explicit development mode and opt-in; tokens require expiry
  and subject claims. Weak/default signing secrets are rejected. RS256 login
  now signs with the matching private key. LDAP search input is escaped and
  connections are released.
- Secured training status, training launch, statistics, database reset and
  WebSocket subscriptions. Launch/reset require admin; response approval
  requires tier3/admin. Training initialization/launch is serialized by Redis.
- Added `/ready` with PostgreSQL and Redis probes, bounded startup checks,
  reconnecting Redis subscriptions, disconnected WebSocket cleanup and token
  expiry enforcement. Database-dependent routes report 503 during an outage.
- API Redis settings and CORS origins honor environment configuration. Database
  credentials are URL-encoded. Missing telemetry returns an error rather than
  a successful zero-filled response; idle training no longer invents accuracy,
  F1, completion or dataset progress. Flow counts are no longer inflated.
- Invalid suppression regexes/CIDRs and absent IP values cannot accidentally
  match a rule. CIDRs entered with host bits are normalized.
- Response routes no longer report simulated enforcement as executed. Queueing
  is supported; enforcement returns 501 until a provider is implemented.
- Dashboard: session-scoped login, sign-out, JSON alert-feed export, service
  readiness indicator, accessible sign-in fields/focus styling, wrapping header,
  authenticated WebSockets, no duplicate initialization timers, no synthetic
  outage fallback, no extrapolation of observed flow totals, and no hardcoded
  model-online claim. Authorization headers are limited to same-origin API calls.
- Added lightweight API dependencies, real regression tests and a GitHub Actions
  Python 3.11/3.12 test workflow. Tests are mocked API/component regressions,
  not full infrastructure integration tests.

## Verification

- 29 regression cases covering authentication/roles, RSA signing, outages,
  readiness, training launch failure/contention, truthful metrics, WebSocket
  authentication/cleanup, suppression matching and response limitations.
- Python compilation for API/config/pipeline; all dashboard scripts parse.
- Local API startup and browser sign-in checked. The dashboard visibly reports
  unavailable services on this host. Docker daemon is not running; PostgreSQL
  and Redis connections are unavailable.

## Remaining limitations

This is a focused security/reliability audit, not a production certification.
Full capture → Kafka → inference → PostgreSQL → dashboard verification, model
quality evaluation and live enforcement require the infrastructure and configured
providers. They were not exercised, and no model was retrained. The pre-existing
local change to `models/invariant_feedback.pkl` is excluded from this commit.

Production work still includes replacing development credentials throughout
pipeline/deployment scripts, dependency locking and vulnerability scanning,
LDAP transport/deployment review, comprehensive escaping of dynamic dashboard
HTML/inline handlers, persistent training-job supervision after API restarts,
and end-to-end tests against real services. Raw telemetry must be treated as
untrusted; do not expose this dashboard to untrusted input without completing
its rendering review. The API reconnects Redis automatically; a database that
was absent at startup requires restarting the API after it becomes available.

The local disk reported almost no free space, so large installs, model training,
and Docker image pulls were intentionally not performed.
